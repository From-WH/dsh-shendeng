# 神灯 · Shen Deng

> 画靶射箭。没有靶，就无的放矢。

一个 DeepSeek Harness 插件：**在动手之前，把模糊的需求收敛成一份能直接执行的说明**。

需求越清晰，AI 的效率和准确率越高；需求越模糊，延迟和错误率越高。神灯处理的就是这件事——把"说不清楚"提前暴露在还来得及纠正的位置，而不是在返工几万 token 之后。

## 安装

在 DeepSeek Harness 的插件管理器中安装本目录，或手动加入 profile：

```yaml
- insert:
    - id: shen-deng
      name: '@local/shen-deng'
      config: {}
```

## 提供什么

### `lamp_refine` — 六维许愿体检

把需求按六个维度过一遍：**交付物、落点、受众与语气、硬约束、验收标准、范围**。
输出：缺哪几项、每项一个推荐默认、一份填好的工作说明。

内置**意图与指代识别**：需求里点名了工作区已有目录（如 "把 shen-deng 再优化一下"），落点自动判定为"改现有"，不再反问"要新建还是改现有"；说"改一下"但没点名时，会列出能对上号的候选。

### `lamp_scan` — 工作区结构

一次有界扫描：深度优先目录树、文件类型统计、项目清单摘要。替代逐个读文件、反复搜索的探索流程。

### 开关与统计

输入框下方一行，点灯亮、再点灭。点亮时提示词段落才注入——需求清楚时零开销。

右侧统计 `已体检 N 次 · 拦截 M 处歧义`，从会话日志精确计数，不是估算。刻意不做"省了多少 token"——那是反事实，无法诚实测量。

### 维度可配置

**设置 → 神灯**：图形界面增删改维度，保存即生效，无需重启。每维五个字段：

| 字段 | 说明 |
|---|---|
| `id` | 唯一标识（必填） |
| `label` | 显示名 |
| `match` | 匹配短语列表；`/…/` 形式按正则处理（必填） |
| `ask` | 向用户提出的问题 |
| `suggest` | 模型可直接采用的默认 |

配置了 `dimensions` 就整体替换内置六维；不配置或留空即用默认。

也可以直接写在 profile 的 `cordis.patch.yml` 里：

```yaml
- id: shen-deng
  name: '@local/shen-deng'
  config:
    dimensions:
      - id: tone
        label: 调性
        match: [幽默, 严肃, 温暖]
        ask: 要什么调性？
        suggest: 默认克制、少形容词。
```

## 设计取舍

- **默认关闭**：体检提示词只在点亮时注入，清楚的需求不付这 600 token。
- **零运行时依赖**：Schemastery 从本地 vendor 引入（linked 包解析不到 profile 依赖）；投影校验是手写的最小实现。
- **不加新事件类型**：开关状态从框架已有的 `command/run` + `command/done` 事件折叠而来，重开、fork 都能还原，旧版本读日志也无害。
- **文字颜色全走主题 token**：深浅主题下都可读。

## 边界

- 只在已有会话显示（`composer.dock` 是 session scope，新对话发出首条消息后出现）。
- 只读工作区顶层结构，不读代码内容；指代识别靠名字对号。
- 体检语料以中文为主，英文需求的识别率会低一些。
